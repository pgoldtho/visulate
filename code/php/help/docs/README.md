# Visulate Help Documentation

This directory (`code/php/help/docs`) serves as the central repository for the Visulate application's user help documentation. It contains a collection of static HTML files, each dedicated to explaining a specific feature, screen, or concept within the property management system. These documents provide users with instructions, explanations, and visual aids (via embedded images from the `images` subdirectory) to navigate and utilize the application effectively. The `index.php` file acts as a simple router, redirecting incoming requests to the appropriate `.html` help file based on a `path` parameter.

## Database Dependencies & Interactions

The files within `code/php/help/docs` are primarily static HTML documents and a PHP redirector. They do not directly interact with any database tables, views, packages, or procedures. Their purpose is to *document* parts of the Visulate application that may have database dependencies, rather than to implement those interactions themselves. The `index.php` file merely handles URL redirection and does not perform database operations.

## Submodules / Subdirectories

-   **`images`**: This directory is a dedicated container for static image assets (screenshots, diagrams, icons) used within the Visulate application's help documentation, serving to provide visual context without containing any executable code or database dependencies.

## Maintenance & Modernization Notes

*   **Legacy HTML Structure**: The HTML files largely adhere to HTML 4.0 Transitional standards and often include inline styling or older HTML elements. Modernization efforts should consider migrating to HTML5, semantic markup, and external CSS for improved maintainability and responsiveness.
*   **Styling**: The documents rely on `vis2008tables.css` and `vis2008layout.css`, which suggests an older design aesthetic. Any redesign of the application's UI would necessitate updating these help files to reflect the new visual identity and style guidelines.
*   **Navigation**: Inter-document navigation is handled via hardcoded `<a>` tags for "Previous" and "Next" links. A more robust help system might integrate a dynamic table of contents or search functionality.
*   **Dynamic Content**: The `index.php` provides a basic routing mechanism. For a more sophisticated help system, a full content management system or a templating engine could be considered to manage help content and potentially inject dynamic elements if needed, though the current content appears purely static.
*   **Accessibility**: Given the age of the HTML, a review for modern web accessibility standards (WCAG) would be beneficial, especially concerning screen reader compatibility, keyboard navigation, and contrast ratios.
*   **Images**: All images are referenced from the `images` subdirectory. Ensure image paths remain consistent if the directory structure changes.
